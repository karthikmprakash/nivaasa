# Nivaasa v1.0.1 — native arm64 and Dokploy

A deployment-focused patch on top of v1.0.0. The product, identity and database schema are unchanged.

## Fixed

- **Native arm64 image.** The production VPS runs `linux/arm64`; the previous image was amd64 only and could not execute (`Exec format error`). The release is now a true multi-arch manifest for `linux/amd64` and `linux/arm64`.
- **Dokploy networking.** The compose service now attaches to Dokploy’s existing external `dokploy-network` instead of asking Docker to allocate a new bridge. This avoids the exhausted address-pool failure on busy hosts.
- **Release packaging.** The brand pack stays attached, and the container package remains public.

## Image

```bash
docker pull ghcr.io/karthikmprakash/nivaasa:1.0.1
```

Also tagged `1.0`, `latest` and the commit SHA. The multi-arch manifest means the same tag works on Intel/AMD and ARM hosts.

## Deploy

The production runbook is [docs/deploy-dokploy.md](https://github.com/karthikmprakash/nivaasa/blob/main/docs/deploy-dokploy.md). The compose file is [`docker-compose.dokploy.yml`](https://github.com/karthikmprakash/nivaasa/blob/main/docker-compose.dokploy.yml).

- Domain: `nivaasa.karthikmprakash.online`
- Service port: `3000`
- Volumes: `nivaasa-data` (SQLite) and `nivaasa-uploads`
- Health: `/api/health`
- First boot seeds the demo; later boots keep the volume.

## Brand

The full identity pack is attached as `nivaasa-brand-v1.0.1.zip` and lives at [brand/](https://github.com/karthikmprakash/nivaasa/tree/main/brand).
