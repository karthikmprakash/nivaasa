# Nivaasa v1.0.2 — many societies, one account

A product patch focused on multi-society membership and the small interface details that make it usable.

## Many societies, one account

- **Switch society anywhere.** The sidebar society card and the account menu now list every active membership. Switching keeps you in the same section when the new role can access it — for example, an admin stays in Billing, and a resident stays in Visitors.
- **Safe role changes.** If you move from an admin membership to a resident-only membership, Nivaasa lands you in the resident app instead of an admin route. Absolute URLs and path traversal are rejected.
- **No duplicate accounts.** Adding a resident or team member whose email already belongs to another society now links a new membership to the existing Nivaasa account. They keep their current password and get access to the new community.
- **Onboarding reuses an existing account.** Creating another community with an email that already has a Nivaasa account works when the account password is entered, instead of asking for a second account.
- **Login remembers the chosen society.** The `nivaasa_society` preference is honoured on the next sign-in.
- **Demo data** now includes the same account in Verdant Heights and Lakeview Residences for the admin, resident and guard personas.

## Admin dashboard header

- The **Run billing** and **Publish notice** actions no longer shrink or wrap their labels between 640px and 760px.
- Below 768px the action group moves onto its own row; above it, the buttons stay aligned to the right of the greeting.
- The society switcher wraps long community names cleanly instead of cutting them off.

## Also in this release

- Visitor pass rules, daily cab passes, gate console and mobile visitor flows.
- Staff attendance helpers and household dialogs.
- The refreshed landing page, community day section and navigation details.
- UI regression coverage for society routing and safe switch destinations.

## Database

The Docker entrypoint runs `npm run db:push` before starting the app. The schema changes in this release are applied in place. The demo seed only runs when the database file does not exist, so an existing volume is **not** wiped on redeploy.

## Image

```bash
docker pull ghcr.io/karthikmprakash/nivaasa:1.0.2
```
