# Nivaasa v1.0.3 — predictable money, private notices, safer roles

A reliability and correctness release. The focus is on the cases that used to drift: permissions, audiences, time zones, invoice totals and stale UI state.

## Access and privacy

- **Direct URLs respect roles.** Admin pages now enforce the same role sets shown in the navigation. An accountant can open Billing and Reports but is sent back from Residents, Settings or Communications; an auditor can read finance and security but cannot mutate them.
- **Read-only roles no longer see dead controls.** Billing, helpdesk, staff, security, settings and resident screens hide verify, edit, assign or publish actions when the role cannot use them.
- **Notice and poll audiences are enforced everywhere.** Owners-only, tenants-only and tower notices are filtered on the web app, mobile API, search and direct notice URLs. Polls follow the same audience rules.
- **Helpdesk assignment is validated.** Only active operational members of the same society can be assigned a ticket.
- **Society team changes are safer.** Only an admin can promote someone to admin or change an existing admin, and the last active admin cannot be demoted.

## Money and billing

- **GST is applied to invoices.** Billing heads carry a GST rate, invoices store the tax amount, and totals, receipts, statements and resident breakdowns all include it.
- **Billing covers the right homes.** A run bills occupied units or units with an active resident membership, and still supports the explicit “include vacant homes” option.
- **Invoice numbers follow the fiscal year.** January–March invoices use the correct Indian financial-year prefix.
- **Duplicate payments are blocked.** A pending offline intimation prevents a second online payment for the same invoice, and cancelled invoices cannot be paid.
- **Receipts tell the truth.** A pending intimation renders as a payment intimation with “Awaiting verification”; only a verified payment is shown as a paid receipt. Rejected payments no longer look successful.
- **Partial data is handled honestly.** Cancelled invoices are excluded from billed totals, and pending payments are excluded from the one-tap “pay now” selection.

## Time, dates and month boundaries

- **Asia/Kolkata is the single source of truth.** Date-only values, `datetime-local` admin inputs, month starts, month keys and open/close checks no longer depend on the server or browser time zone.
- **Impossible dates are rejected.** Values such as `2026-02-31` are refused instead of silently rolling into March.
- **Late fees, gate history and dashboards use community boundaries.** “Today”, “this month” and the last six months are calculated the same way across the resident app, admin console, reports and mobile API.
- **Full-day amenities work.** The Guest Suite’s 12:00–11:00 window is bookable, while normal slots still reject times that have already passed.

## Gate, helpdesk and alerts

- **Gate actions are audited.** Visitor exits, parcel handovers, patrol scans and emergency acknowledgements now write audit entries.
- **Patrol scans are idempotent.** Scanning the same checkpoint twice in one day does not create duplicate rounds.
- **Panic alerts notify both directions.** Residents are told when security acknowledges or resolves an alert; guards are told when a resident marks themselves safe.
- **Helpdesk SLA updates follow priority.** Reopening or changing priority recalculates the SLA deadline, and unassigned replies notify the helpdesk team.

## Reliability and polish

- Polls, gate queues, deliveries and alerts refresh when server data changes instead of keeping stale local state.
- Notice views are tracked from a client component, so link prefetching no longer inflates the count.
- Notice deletion removes the matching notifications; poll closure, listing removal and other moderation actions are audited.
- CSV exports neutralise spreadsheet formula injection.
- Society switching from a detail page keeps the section instead of landing on another society’s 404.
- The admin dashboard hides finance, helpdesk or security cards the current role cannot open.
- Receipt status and pending-payment states have explicit regression coverage; the full-day Guest Suite path is covered by the production smoke test.

## Database

The Docker entrypoint runs `npm run db:push` before starting the app. This release adds the `discussion_likes` table in place. The demo seed only runs when the database file does not exist, so an existing volume is **not** wiped on redeploy.
